# Starter prompt for a coding agent

Copy the following prompt into your coding agent after cloning this repository.

---

You are setting up Aurelle, a TypeScript strict Next.js shopping-agent demo. Work in this repository and follow its AGENTS.md. Keep code, comments, UI and documentation in English and prices in EUR; assistant replies should follow the customer language. Do not deploy, publish, change DNS, create accounts, rotate credentials or purchase services unless the user explicitly asks.

1. Read README.md, package.json, .env.example, docs/VERIFICATION.md and the domain/application/composition contracts before changing anything. Preserve unrelated work. Use the actual scripts, not guessed commands. Check Node (22+) and platform support; native LanceDB/ONNX require a supported Linux/macOS/Windows architecture. Explain FreeBSD limitations instead of claiming a working install.
2. Run npm ci. Inspect whether `.env.local` already exists without printing secrets; never overwrite it. If it is missing, copy `.env.example` and preserve its defaults.
3. Check the server configuration without printing secrets. The demo uses the shop's `GROQ_API_KEY` and direct Groq GPT-OSS 120B on every inference. A local server may read `API_KEY` from an existing private file via `AURELLE_GROQ_KEY_FILE`. Never place a key in a client variable, a browser request or Git.
4. For broad local QA, use the loopback-only test mode in README.md with a tool-capable test model. Verify the reported model from the provider response. Preserve the small 120B acceptance budget for real demo requests. If you have no chat key you can still prepare the catalog and run the controlled tests.
5. Run npm run catalog:prepare. This downloads the pinned BGE small q8 embedding encoder (about 34 MB) and builds real LanceDB records. This CPU encoder is separate from the chat model and needs no GPU. Keep the cache and DB out of Git; no keyword-only substitute.
6. Run npm test, npm run typecheck and npm run build for the final inputs. Start npm run dev, confirm its actual port and inspect the application in a browser.
7. Verify the complete flow: the catalog has 86 products across ten categories; category/search controls work; Enter sends and Shift+Enter inserts a line; product pages and unknown IDs behave correctly; add to cart from both a product page and a chat card; update quantities, reload, remove; test unavailable products and malformed local storage without damaging user data. Verify chat + draft persistence after product navigation/Back/reload, New conversation while a response is pending, the welcome message and the coffee starter returning relevant cards.
8. Run `npm run test:agent:dry` after preparing the MiniLM cache. For real-provider acceptance, build and run the app with the chosen provider, verify its actual model in runtime configuration or logs, then run `npm run test:agent:live -- <app-url>`. The runner saves transcripts and simulates browser cart writes; inspect its results and test actual browser storage separately. Check PL/EN shopping, refinements, categories, comparisons, cart selection, unsupported features and provider errors. A successful models endpoint or fixture run is not end-to-end provider evidence.
9. Run npm run test:e2e after installing Chromium; for Docker packaging use npm run container:smoke. Check desktop and 390 px mobile views, keyboard focus, overflow, empty/loading/error states and readable feedback. Make corrections within the authorized scope. Keep the visual style documented in DESIGN.md.
10. Finish with a concise report: actual URL, commands and outcomes, selected provider/model, tested vs untested paths, changed files and any specific user-only step remaining. Do not claim universal model reliability. Link any local setup changes in README/verification notes if they alter the supported workflow.
